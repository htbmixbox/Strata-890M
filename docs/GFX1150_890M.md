# Radeon 890M / 880M (gfx1150, Strix Point): what is on by default, and how to set up a 96 GB machine

The 890M (Ryzen AI 9 HX 370 / 470, RDNA3.5, 16 CUs, one pool of DDR5 shared with the CPU) runs through the HIP backend
(see [AMD_HIP.md](AMD_HIP.md#rdna2-gfx1030), the gfx1150 entry). Until this change it ran the engine's plain defaults: the
exact speed switches of [STRIX_HALO.md](STRIX_HALO.md) section 4 were gfx1151-only, and the hipBLASLt table had to be
named by hand. Everything below comes from one community machine
([bench/results/2026-10-07-community-gfx1150](../bench/results/2026-10-07-community-gfx1150/README.md): MINISFORUM N5 PRO,
96 GB DDR5-5600, IQ3_XXS). **It has not been re-measured on the machine you run it on: compare before you keep it.**

## On by default on gfx1150

At start the engine looks at GPU 0. On a gfx1150 it sets, unless you set them yourself:

- **The 17 exact switches** of the gfx1151 table, all but `STRATA_HCD_EXACT` (it copies gfx1151's hipBLASLt solutions
  1176 / 1177; the gfx1150 table picks others, so it would do nothing). On the 890M the same greedy answers came out with and
  without them (also a 13,969-token prompt); decode 14.9-15.0 -> 15.2-15.3 tok/s (+2%, in every pair), prompts +2.1 to +6.0%.
- **`STRATA_HIPBLASLT_TUNING`** = `tools/hip/gfx1150-hipblaslt-100401.txt`, when the variable is not set and the file is under
  the working directory or next to the engine (the executable's directory and four parents up). Prompts read 1.5-1.7x faster
  with it (3.6K tokens 124 -> 216 tok/s, 7K 130 -> 226 tok/s; decode unchanged). The table is for hipBLASLt 100401 (ROCm
  7.14.1) only: on another ROCm the engine says `hipBLASLt version mismatch` and keeps plain hipBLAS, as before.

`STRATA_GFX1150_DEFAULTS=0` turns both off. A switch or a table you set yourself is never replaced. The start-up line names
what was set.

## Opt-in: rounding-level prompt switches (they change bits)

Not in the default table: they round differently from the default path, so answers can differ in the last digits. On the
890M, one run each added alone to table + switches (prompts of about 1K / 3.6K / 7K tokens; the base read 153 / 217 / 230):

| Switch | Prompt tok/s |
|---|---|
| `STRATA_HIP_WMMA=1` | 160 / 250 / 277 (+20% at 7K) |
| `STRATA_PF_FUSED=1` | 155 / 257 / 255 |
| `STRATA_PF_GEMM=1` | 166 / 243 / 262 |
| `STRATA_PA_FAST`, `STRATA_SELECT_WMMA`, `STRATA_HC_UPMIX` | unchanged |
| `STRATA_HC_Q8=1` | 146 / 219 / 224 (slower) |

Decode did not move with any of them. To make them easy to try:

- `STRATA_GFX1150_FAST=1` sets `STRATA_HIP_WMMA=1` (the best single one).
- `STRATA_GFX1150_FAST=2` sets `STRATA_HIP_WMMA`, `STRATA_PF_FUSED`, `STRATA_PF_GEMM` and `STRATA_PF_SWITCH_MIN_T=4096`.
  **These were not measured together on a 890M**, and a bigger set is not automatically faster there: all seven switches of
  [STRIX_HALO.md](STRIX_HALO.md) section 5 together, on that machine without the table, read 83 tok/s at 3.6K where the exact
  switches alone read 124. Run `./bench.sh` (or a fixed prompt) with FAST unset, 1 and 2, the same day, and keep what wins.

## A 96 GB machine: memory

The GPU's memory is the GTT pool of the same RAM, capped by the kernel's `ttm.pages_limit` (the default is about half the RAM).
`tools/hip/gfx1150-memory-check.sh` reads the pool and the BIOS carve-out (it changes nothing) and prints a value if the pool
is smaller than RAM less 16 GiB. For 96 GB that is 80 GiB, in 4 KiB pages:

```
ttm.pages_limit=20971520 ttm.page_pool_size=20971520
```

Add it to the kernel command line and reboot. The measured machine used 16777216 (64 GiB), which holds every expert of an
IQ3_XXS pack (24,576 experts, 39.97 GiB) with room for the KV cache and the prompt buffers; a bigger pool matters for bigger
packs or longer contexts. Keep the BIOS carve-out small (512 MiB on the measured machine): the engine uses the GTT pool, and
a large carve-out only takes RAM from the system.

Run with all experts in the pool (`--mmap-experts --expert-cache <number of experts>`), as the measured config does
([strata-gfx1150.json](../bench/results/2026-10-07-community-gfx1150/strata-gfx1150.json)). Give `--expert-cache` a number
rather than `auto` when you also keep a large `--conversation-cache-mib`: `auto` counts what the OS can give back at start
(MemAvailable less `STRATA_UMA_HEADROOM_GIB`, 6) and does not know what the conversation cache will take later.

## What is not done here

- Decode is not changed. It reads the experts from RAM, and the measured machine's 15 tok/s did not move with any prompt switch;
  faster RAM is the lever that is known to matter, not a switch. `--spec`, `--mtp-q4`, `--lookup-chain` and a smaller quant
  are the engine's own options for it (see [DETAILS.md](DETAILS.md)).
- Setup (`setup.sh`, `START-HERE.bat`) still does not install for gfx1150: build by hand with `-DCMAKE_HIP_ARCHITECTURES=gfx1150`
  ([STRIX_HALO.md](STRIX_HALO.md) section 2 with the architecture changed).
- Nothing here was run on a GPU by the author of the patch: the unit test (`arch_defaults_test`) and the table lookup were
  built and run, the kernels were not.
